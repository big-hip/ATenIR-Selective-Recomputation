## 1. 问题诊断

### 1.1 历史数据（stale）

以下数据来自旧实现，用于解释 L2.5 的设计动机，不再作为当前论文 MRE 结论。旧版 L2.5 曾使用"非 extern 即 fusable"的宽口径，可能过度消除并低估部分策略。

L2 (`estimate_graph_peak`) 对不同后端的精度差异巨大：

| 后端 | L2 MRE 范围 | 方向 | 原因 |
|------|------------|------|------|
| aot_eager | 1-2% | 略低/略高 | 图结构 ≈ 实际执行 |
| inductor | **28-47%** | **总是过高** | 图中间 tensor 被融合消除 |

ex5 (LLaMA 6L/512H, batch=8, SGD) 详细数据：

| 策略 | RT peak | L2 peak | L3 peak | L2 MRE | L3 MRE |
|------|---------|---------|---------|--------|--------|

| aot_eager+min_cut | 962 MB | 951 MB | — | 1.2% | — |

### 1.2 根因：ATen IR 中 Fusable Tensor 占比极高

对 LLaMA 6L/512H batch=8 的 ATen IR 进行 op 分类统计：

```
Forward graph:
  Extern (mm/bmm/sdpa):  55 nodes,  281.0 MB  ← 不可融合
  Pointwise/Fusable:    230 nodes,  625.7 MB  ← 可被融合消除！
  Fusable 占比: 69.0%

Backward graph:
  Extern (mm/bmm/sdpa):  110 nodes, 304.5 MB  ← 不可融合
  Pointwise/Fusable:     490 nodes, 1675.8 MB ← 可被融合消除！
  Fusable 占比: 84.6%
```

L2 把所有 1675.8 MB 的 BW pointwise tensor 都当作独立分配，但 Inductor 会将它们
融合为少量 Triton kernel，**中间 tensor 从不在 GPU 上物化**。

### 1.3 误差来源分解

```
L2 过高估计 = Fusion未建模(~80%) + Buffer Reuse未建模(~15%) + In-place优化(~5%)
```

## 2. Inductor Fusion 机制概要

### 2.1 Node 类型（Inductor Scheduler 的分类）

```
ir.ComputedBuffer  →  SchedulerNode       →  可融合 (pointwise/reduction)
ir.TemplateBuffer  →  SchedulerNode       →  可融合 (template epilogue)
ir.ExternKernel    →  ExternKernelSchedulerNode → 不可融合 (mm/bmm/conv/sdpa)
ir.NopNode         →  NopKernelSchedulerNode    → 不可融合
```

### 2.2 融合规则（`Scheduler.can_fuse`，L3082-3148）

1. **ExternKernel 不可融合**（除 template epilogue）
2. 两个 SchedulerNode 可融合当且仅当：
   - 同一设备
   - 无循环依赖
   - 共享数据 score > 0（有共同读写的 buffer）
   - 通过 backend 的 `can_fuse_vertical` 或 `can_fuse_horizontal` 检查
3. **Vertical fusion**（producer→consumer）：consumer 的所有输入要么来自 producer，
   要么可以在 fusion 前调度
4. **Horizontal fusion**（无依赖关系的并行 node）：共享读取的 buffer

### 2.3 融合后果对内存的影响

融合前（两个独立 kernel）：
```
kernel_1: input_A → [alloc temp_B] → output_B
kernel_2: input_B → [alloc temp_C] → output_C
GPU memory: A + B + C 同时存在
```

融合后（单个 kernel）：
```
fused_kernel: input_A → [temp_B 在寄存器/shared mem] → output_C
GPU memory: A + C 同时存在, B 从不物化
```

**关键洞察**：fusion group 内部的中间 tensor 从不在 global memory 分配。

## 3. L2.5 设计方案

### 3.1 整体架构

```
estimate_graph_peak (现有 L2)
        │
        ▼ 新增: fusion_aware=True
estimate_graph_peak_fusion_aware (L2.5)
  ├── Step 1: Op 分类 (extern vs fusable)
  ├── Step 2: Fusion Group 识别
  ├── Step 3: 标记 group 内部中间 tensor 为零分配
  └── Step 4: 在修正后的分配集合上做 live-range 分析
```

### 3.2 Step 1: Op 分类

将 ATen IR 中的 `call_function` / `call_method` 节点分为三类：

```python
# 不可融合的 Extern ops (对应 Inductor 的 ExternKernelSchedulerNode)
EXTERN_OPS = {
    # GEMM 类
    torch.ops.aten.mm.default,
    torch.ops.aten.bmm.default,
    torch.ops.aten.addmm.default,
    # SDPA 类
    torch.ops.aten._scaled_dot_product_flash_attention.default,
    torch.ops.aten._scaled_dot_product_efficient_attention.default,
    # Convolution
    torch.ops.aten.convolution.default,
    torch.ops.aten.convolution_backward.default,
    # BatchNorm
    torch.ops.aten._native_batch_norm_legit_functional.default,
    torch.ops.aten.native_batch_norm_backward.default,
    # 其他
    torch.ops.aten._flash_attention_forward.default,
    torch.ops.aten._flash_attention_backward.default,
    torch.ops.aten._efficient_attention_forward.default,
    torch.ops.aten._efficient_attention_backward.default,
}

FUSABLE_OPS = {
    # 保守 allowlist：简单 unary/binary/activation/mask pointwise
    torch.ops.aten.add.Tensor,
    torch.ops.aten.mul.Tensor,
    torch.ops.aten.relu.default,
    torch.ops.aten.sigmoid.default,
    torch.ops.aten.tanh.default,
    torch.ops.aten.where.self,
    ...
}
```

**分类原则**：
- 在 Inductor 中由 CUBLAS/cuDNN/Triton template 实现的 → `extern`
- 明确、shape-preserving、低风险 pointwise → `fusable`
- unknown/materializing op 默认 → barrier，不做 internal 消除
- View ops 已由现有 `is_view_node` 处理 → 跳过（零分配）

当前暂不消除：embedding/gather/scatter/clone/random/layout-changing ops 和复杂 reduction。这个选择牺牲一部分 L2.5 乐观收益，但优先避免低估。

### 3.3 Step 2: Fusion Group 识别

**算法：贪心拓扑扫描**

```python
def identify_fusion_groups(nodes, node_size):
    """
    识别可融合的 op group。
    
    规则:
    1. Extern/unknown/materializing node 是 fusion barrier, 自成一组且必定物化
    2. 只有 is_fusable_op(node)==True 的节点可加入 producer group
    3. 一个 fusable node 的输出如果只被同 group 的 nodes 消费, 标记为 "internal"
    4. Internal tensor 分配大小设为 0
    
    Returns:
        dict[fx.Node, int]: group_id for each compute node
        set[fx.Node]: internal nodes (zero-alloc)
    """
    group_id = {}
    next_gid = 0
    
    for node in nodes:  # 拓扑序
        if node.op in ('placeholder', 'output'):
            continue
        if is_view_node(node):
            continue
        if node not in node_size:
            continue
        
        target = getattr(node, 'target', None)
        
        if not is_fusable_op(node):
            # Extern/unknown: 自成一组, 是 fusion barrier
            group_id[node] = next_gid
            next_gid += 1
        else:
            # Fusable: 尝试加入某个输入节点的 group
            input_groups = set()
            for inp in node.all_input_nodes:
                if inp in group_id and is_fusable_op(inp):
                    input_groups.add(group_id[inp])
            
            if len(input_groups) == 1:
                # 唯一的 fusable 输入 group → 加入
                group_id[node] = input_groups.pop()
            elif len(input_groups) > 1:
                # 多个 group 汇合 → 创建新 group (保守策略)
                group_id[node] = next_gid
                next_gid += 1
            else:
                # 无 fusable 输入 → 新 group
                group_id[node] = next_gid
                next_gid += 1
    
    # 识别 internal nodes: 所有 consumer 都在同一 group 中
    internal = set()
    for node, gid in group_id.items():
        if not is_fusable_op(node):
            continue  # barrier 输出必须物化
        
        users = [u for u in node.users if u.op != 'output']
        if not users:
            continue  # graph output, 必须物化
        
        all_in_group = all(
            group_id.get(u) == gid or is_view_node(u)
            for u in users
        )
        if all_in_group:
            internal.add(node)
    
    return group_id, internal
```

## 4. 预期效果分析

### 4.1 理论上界

BW 中 fusable tensor 占比 84.6%。假设 fusion 消除 60-70% 的 fusable 中间 tensor：
- BW total alloc 减少: 1675.8 MB × 60% = ~1006 MB
- 但 live-range 分析下峰值不等于总分配，实际降低比例取决于重叠模式
- 保守估计 L2 MRE 从 28-47% 降至 10-20%

### 4.2 局限性

| 局限 | 原因 | 影响 |
|------|------|------|
| 低估风险 | 即使使用 allowlist，真实 Inductor fusion 仍受 backend 规则影响 | 需用 L3/Runtime 校准 |
| 保守高估 | unknown op 默认 barrier，部分真实可融合节点不会消除 | L2.5 可能比旧版更高 |
| 水平融合未建模 | 只建模 vertical fusion (producer→consumer) | 影响小 |
| Reduction 融合规则复杂 | Inductor 对 reduction 有额外约束 | 当前复杂 reduction 默认 barrier |
| 版本依赖 | EXTERN_OPS 集合随 PyTorch 版本变化 | 需维护 |
| Buffer reuse 近似 | safe reuse 禁止 placeholder/输出/参数 alias，且重计算 BW 禁用 | 可能保守高估 |

### 4.3 精度结果

| 估算层 | aot_eager MRE | inductor MRE | 需GPU? | 说明 |
|--------|--------------|-------------|--------|------|
| L1 (公式) | 15-25% | — | 否 | 配置级估算 |
| L2 | 1-7% | 28-38% | 否 | ATen IR live-range |
| **L2.5 fusion-only** | **—** | 待重跑 | **否** | **只做 fusion elimination** |
| **L2.5 safe-reuse** | **—** | 待重跑 | **否** | **fusion + 保守 reuse** |
| L3 | — | 待重跑 | 是 | Inductor Scheduler + input 诊断 |

### 8.3 动态检测策略

为避免维护静态列表，可以用一个运行时检测方法（在初次调用时缓存）：

```python
def is_extern_in_inductor(aten_op):
    """Check if an aten op becomes ExternKernel in Inductor lowering."""
    from torch._inductor.lowering import lowerings
    if aten_op not in lowerings:
        return True  # not lowered → fallback → ExternKernel
    # For ops in lowerings, we need the static EXTERN_OPS set
    # because lowerings includes both pointwise and extern lowerings
    return aten_op in EXTERN_OPS
```
